# 02 — 플레이 전략 / 목표 배치 (사용자 지침)

2026-09-16 사용자 제공 + 확인 완료. 봇(M3 룰 엔진)이 달성해야 할 목표 상태.

## 덱 (5종)

포식(Predator) / 빛(Light) / 공명(Resonance) / 버블(Bubble) / 스위치(Switch)
스프라이트 매핑(확인됨): `Dice_Predator` / `Dice_Light` / `Dice_Resonance` / `Dice_BUBBLE` / `Dice_Switch`
→ 인식(M1)은 이 5종 + 빈칸만 구분하면 됨 (52종 전체 불필요)

## 배치 우선순위 / 버프 (2026-09-16)

- **포식 배치 우선순위: #1 > #11 > #3** (부분 상태·복구 시 이 순서로 확보)
- **빛은 포식 근처 우선.** 빛 버프 범위 = **주변 8칸(3×3 이웃)**.
  고정 배치가 이미 빛→포식 커버 최적: #7(중앙 r1c1)이 포식 #1·#3·#11 모두 커버,
  #2→#1#3, #6→#1#11, #8→#3, #12→#11. 각 포식이 여러 빛에 중첩 커버됨
- → 배치/복구 시 포식 먼저(#1), 빛은 포식 인접 셀 우선 채움

## 목표 배치 (5열 × 3행, 셀 번호 = 행우선 좌상단 기준 — 확정)

```
#1 포식   #2 빛    #3 포식  #4 n    #5 n
#6 빛     #7 빛    #8 빛    #9 n    #10 n
#11 포식  #12 빛   #13 n    #14 n   #15 n
```

- 포식 ×3 (고정): #1 #3 #11
- 빛 ×5 (고정): #2 #6 #7 #8 #12
- n(가변칸) ×7: #4 #5 #9 #10 #13 #14 #15

## 규칙 (확정)

1. **n칸 구성 (2026-09-16 정정)**: n칸 7개 안에 **버블 ≥1(pip무관) + 공명 ≥3(pip1)** 필수.
   **스위치 1(pip1)은 필수 아님 — 권장 예비**: 포식·빛 배치 끝나면 지워도 완성이나,
   나중에 필드변경효과로 무너졌을 때 빠른 복구용으로 1개 남겨두길 권장.
   완성 필수 구성: 포식3(pip1) 빛5(pip≥1) 공명≥3(pip1) 버블≥1 = 12/15 (+ 스위치1 예비 + 돈케어2).
2. **스위치**: 최종 배치에 고정 위치 없음. **배치 조정용 임시 도구**.
   메커닉: **스위치를 같은 눈금(pip)의 주사위 위로 드래그하면 두 주사위 위치가 서로 바뀜**(swap).
   → 파괴 없이 잘못 놓인 주사위를 올바른 칸으로 이동시키는 수단. 청 파괴(쿨90s)보다 저렴
3. **눈금 일치**: 모든 포식(3개) + 공명(≥3개)은 **눈금(pip)이 서로 같아야 함. 값 자체는 무관**
   (전부 1이든 2든 상관없고 "같기만" 하면 됨). 빛·버블 눈금은 무관.
4. **정밀 배치 덱**: 1눈금 상태로 정확한 위치에 놓는 것이 핵심. 위치 정확도 > 눈금 올리기.
5. **서포터 = 청(Cheong)**: 주사위를 **청 서포터 아이콘 위로 드래그**하면 그 주사위 **파괴**. 쿨타임 90초.
   - 용도: 잘못 소환/배치된 주사위 제거 → 목표 배치 복원
   - 청 아이콘 좌표(확정): **u≈0.19, v≈0.867** (소환 버튼 왼쪽 노란 버튼).
     실사용 파괴 드래그 2건 종점 (0.176,0.872)/(0.206,0.862) + 육안(중산모 흰 캐릭터) 일치.
     발동 = 대상 주사위 셀 → 이 좌표로 드래그

## 자율 루프 알고리즘 (사용자 지정, 2026-09-16)

```
1. 게임 시작 → 소환을 마구 해서 필드를 채운다
2. 채우면서 스위치로 지정된 자리에 배치
3. 지정 자리 다 채워지면 → 불필요한 주사위를 스킬(청 파괴) 또는 합성으로 제거
4. 요구치(목표 배치) 충족되면 → 대기(idle)
5. 대기 중 필드효과·보스스킬 등 "사고"로 요구사항 미달 감지 → 다시 배치 루프(1~3) 반복
```

- **SP 경제 무시 가능** — SP 소모처는 소환·강화뿐. 신경 안 써도 됨
- **팝업(보스/필드효과) 완전 무시** — 선택이 아니라 공지. 팝업 동안 조작만 잠시 막힘
  (주입해도 씹히므로 안전). 봇은 팝업을 회피할 필요 없음

## 배치 시뮬레이션 결과 (2026-09-16) — 스킬 최소화

**병목 = 스킬(청 파괴) 사용 횟수** (90초 쿨). 소환·합성은 노쿨(무제한), 스위치는 쿨타임 있음.
그래서 최적화 목표 = **파괴 횟수 최소화** (총 액션 수가 아님).

메커닉 (사용자):
- **소환 = 20% 균등 랜덤 5종**, pip1
- **합성 = 같은 (종류,pip) 2개 → 랜덤 20% 1개(pip+1), 한 칸 비움** (랜덤다이스 핵심 = 합성도 리롤!)
- **파괴 = 스킬**, 한 칸 비움, 90초 쿨
- **효율 기법**: 초과분 2개 합성(한 칸↓, 노쿨) → 합성물 파괴(한 칸↓, 스킬1) = **스킬 1번에 두 자리**

시뮬(`src/rdom/sim/`, `tools/sim_bench.py`) 3000회, 빈 보드→목표:

목표: 포식3(pip1) 빛5 공명≥3(pip1) 버블≥1 = 12/15 (+스위치1 예비 +돈케어2).

**백테스트 300회** (`tools/sim_backtest.py`), 초기 빌드(빈 보드→목표):

| 방식 | 평균 스킬 | 소환 | 합성 | **최악** |
| --- | --- | --- | --- | --- |
| 파괴 전용 (naive) | 13.3 | 28.3 | 0 | 50 |
| 합성 우선 (min_skill) | 6.2 | 25.3 | 4.2 | 41 |
| **적극 합성 (eager)** ★ | **6.2** | 25.3 | 4.2 | **28** |
| eager + 편향 소환 | 4.9 | 22.0 | 2.5 | 61 |

**복구 시나리오** (목표→필드변경 k칸 교란→목표): k=2 → 3.3스킬, k=3 → 4.1, k=5 → 5.0.
필드변경 피해 복구는 스킬 3~5로 저렴.

**핵심 발견:**
1. **적극 합성(eager)이 최적** — 평균은 min_skill과 같으나(6.2) **최악 케이스 41→28로 32% 개선**.
   초과분을 즉시 합성해 리롤을 앞당겨 분산을 줄임 → 봇이 더 예측 가능하게 수렴
2. **합성 우선이 파괴 전용 대비 2.2배 절감** (13.3→6.2). 편향 소환 가능하면 4.9
2. **합성이 공짜 리롤** — 초과분 2개 합성하면 한 칸 비면서 40% 확률로 필요한 빛/버블이 나옴(pip 무관).
   빛/버블은 pip 상관없어 합성 결과 그대로 활용 가능
3. **파괴는 최후수단** — 합성으로 못 비울 때만. 스위치=빈칸정렬이라 배열 자체는 저렴
3. **스위치 1개 예비 보존**(pip1) — 완성 필수는 아니나 복구용. 시뮬상 스킬은 안 줄지만(배열을 공짜로
   모델링) 실전에선 복구 시 새 스위치 소환·대기를 아껴 **시간**을 줄임(사용자 권장 근거는 시간)
4. **배치 우선순위**: 포식 #1>#11>#3, 빛은 포식 인접 우선(버프 8칸). 부분/복구 시 적용

**권장 라이브 알고리즘 (eager, 스킬 최소):**
- 초과분 2개가 같은 (종류,pip)면 **즉시 합성**(리롤·자리비움, 노쿨) — 앞당겨 분산↓
- 빈칸 있으면 소환으로 채움
- 포식·공명은 **소환분(pip1)만** 유지 (눈금 정렬 위해 합성 금지)
- 스위치 1개(pip1) 예비 보존
- 합성으로 못 비울 때만 파괴(스킬). 스위치로 목표칸 배열(우선순위 순)
- **대기 중 복구 루프**: 필드변경효과로 무너지면 예비 스위치로 재배치, 부족분만 재소환/합성 (스킬 3~5)
- **실전 보정(시뮬 미반영)**: 스위치 쿨타임

## 라이브 인식 보정 (2026-09-16)

- **상대 노란빛 버프 → 오인식**: 화면에 노란 색조가 입혀져 주사위가 전부 tan(=Predator)으로 몰림

- **안전망**: 한 종류 8개 초과로 읽히면(오인식 신호) 그 프레임 배치 스킵 (`bot_live` play_battle)
- **풀 오토플레이 실전 검증(10분+ 게임)**: 소환1510, 스위치114(~5s당1, thrash아님), 오인식게이트 2회,

## 특이 케이스 (덱 외 방해물, 2026-09-16)

- **폭탄 주사위(검정)**: 특수효과로만 나오는 덱 외 주사위, 배치 방해. **즉시 제거.**
  인식: 매우 어두움(어두운비율 V<80 > 0.45; 덱 ≤0.25, 빈칸 ~0). `board._dark_frac`→"Bomb".
  처리: `plan_next` 최우선 — 인접 주사위로 드래그 합성, 없으면 청 파괴. **구현·검증 완료**
- **수정(crystal) 필드 구조물**: 상하좌우 인접에서 **7회 합성**하면 사라짐. 빠른 제거 중요.
  처리: `plan_next` — 수정 인접 셀에서 합성 우선(`_mergeable_among`). **로직 구현됨**.
  **인식 미완** — 실물 프레임 필요(색/모양 캘리브레이션). 실제 수정 나오면 캡처해 임계값 확정

## 주사위별 상태 (인식 단서)

- **빛(Light)**: 상태변화 없음 (쿨타임 없음)
- **버블(Bubble)**: **쿨타임이 돎** (타이머 표시) ← 빛과 구분하는 핵심 단서
- **스위치(Switch)**: 쿨타임 있음. **쿨타임은 사람·눈금·확률(사용해도 안 걸릴 수 있음)에 따라 달라** 고정 타이머 불가
  → **die의 쿨타임 게이지(우상단 어두운 부채꼴)를 시각 검출.** `perception.board.switch_on_cooldown`
  (V<140 어두운비율: 준비 ~0.002-0.02 vs 쿨타임 ~0.095, 임계 0.05). `any_switch_ready`로 판정,
  라이브 배치에서 준비된 스위치 없으면 스위치 배치 스킵(thrash 방지)
- → 빛↔버블 혼동은 쿨타임 오버레이 유무로 해소 가능 (M1 개선 포인트)
